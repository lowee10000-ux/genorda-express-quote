# 运价 JSON 格式

浏览器导入的是 JSON 数据包，不是可执行 JavaScript。文件在当前页面本地解析，不上传；导入的运价不写入浏览器持久存储，刷新后恢复公开演示数据。

## 顶层结构

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `schemaVersion` | 数字 | 当前为 `1` |
| `metadata` | 对象 | 数据名称、性质、币种、日期和来源 |
| `destinations` | 数组 | 目的地条目、分区和各服务的不可用标记 |
| `rates` | 对象 | IP、IE、IPE 的按件价格和大货每公斤价格 |
| `rules` | 对象 | 重量进位、包装上限及明确配置的免燃油分区 |

导入后的数据性质与生效日期都取决于文件提供者填写的信息，不能据此推断承运人已经接受货物。

## 元数据

```json
{
  "kind": "custom",
  "name": "本地业务运价",
  "currency": "CNY",
  "effectiveFrom": null,
  "effectiveTo": null,
  "source": "由使用者自行核对的数据"
}
```

`kind` 为 `demo` 或 `custom`。`demo` 表示合成演示数据；`custom` 仅表示用户导入的数据，不表示已核验。已知有效日期使用 `YYYY-MM-DD`，不明时保留 `null`，不要填入推测日期。当前金额以人民币（`CNY`）计算和展示，不提供汇率换算。

## 目的地

```json
{
  "cn": "目的地示例",
  "en": "Example Destination",
  "zh": "目的地示例",
  "ip": "A",
  "ie": "A",
  "ipe": "A",
  "ipNA": false,
  "ieNA": true,
  "ipeNA": true,
  "note": "示例分区，请按本票确认"
}
```

`cn` 是简体名称，`en` 是英文名称，`zh` 是繁体或其他中文名称。`ip`、`ie`、`ipe` 是各服务对应的价表分区。`ipNA`、`ieNA`、`ipeNA` 为 `true` 时，该记录不允许使用对应服务试算。

目的地可以是国家、地区或州级条目。应使用能够唯一识别目标的名称；例如美国分区不能只凭模糊词自动假定。示例文件中的可用性标记是静态样例，不能替代承运人当期确认。

## 价格表

以下是字段说明片段，不是一份覆盖全部重量和服务的完整导入文件：

```json
{
  "IP": {
    "piece": {
      "Package": { "A": { "0.5": 100, "1.0": 120 } },
      "Pak": { "A": { "0.5": 90, "1.0": 105 } },
      "Envelope": { "A": { "ENV": 80 } }
    },
    "perkg": {
      "A": [[21, 44, 20], [45, 70, 18], [71, 99, 17]]
    }
  }
}
```

### 按件价格 `piece`

结构为“包装 → 分区 → 重量档 → 金额”。Package 和 Pak 的重量键保留一位小数，例如 `"0.5"`、`"1.0"`；Envelope 使用 `"ENV"`。金额是该档的总运费，不是每公斤价格。

价表缺少某一组合或重量档时，应交由人工查询，不应从相邻条目臆算。IE 仅使用 Package；其他包装是否可用仍需由价表和本票条件确认。

### 大货价格 `perkg`

每个三元组为 `[起始重量, 结束重量, 每公斤价格]`，边界包含首尾。先按 `rules.bulkStep` 对重量向上进位，再匹配价带，以“该档每公斤价 × 计费重量”计算。

例如在演示规则下，44.1 kg 向上进位为 45 kg，匹配 `[45,70,...]`，不会落在 44 与 45 之间的空隙。每公斤价不代表大货总价。大货试算只支持 Package，且适用的最高重量取决于价表覆盖范围。

所有价格和费率应是有限、非负数值，不能用空字符串、`NaN`、`Infinity` 或文本代替金额。数据文件应按实际合同核对币种、单位、重量档、服务及适用日期。

## 计算规则

```json
{
  "pieceMaxWeight": 20.5,
  "pieceStep": 0.5,
  "bulkMinimum": 21,
  "bulkStep": 1,
  "pakMaxWeight": 2.5,
  "envelopeMaxWeight": 0.5,
  "fuelExemptZones": []
}
```

这是项目的演示配置，不是承运人的通用标准。修改时需要同步核对对应价表和实际业务条件。输入重量及规则中的重量值最多支持 6 位小数；进位采用十进制整数单位计算，避免自定义步长的浮点误差。

免燃油仅来自 `fuelExemptZones` 的显式配置；不能因为分区名为 `J` 就自动认定免燃油。默认空数组表示没有免燃油分区。危险品收费与包装限制也不能仅由重量推导，勾选 DG 不会产生承运批准。

公司抬头、燃油费率、DG 费、过港费、最低收费、加价率和有效期由页面参数设置提供，不属于这份运价数据包。示例费率及有效期只能用于演示，投入业务前应逐项调整并核对。

## 转换旧文件与保密

```sh
node scripts/convert-rates.mjs "path/to/rates.js"
```

输入文件应包含 JSON 兼容的 `RATES` 和 `ZONE_MAP` 声明。转换器只提取并解析这些数据，不运行文件。转换结果默认存放在已忽略的 `.private/rates.private.json` 中。

本地导入有助于避免意外把实际价格放进公开仓库，但不能让前端加载的数据对使用该浏览器的人保密。不要将 `.private/`、原始实际运价、客户资料或加价策略上传到公开仓库、公开 Issue 或公开静态托管目录。
